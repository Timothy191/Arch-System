# Business Loop: Post-Deployment Self-Improving Validation

## 1. Business Intent

Ensures the system automatically evaluates capability gaps following every deployment (local or staging). If the live environment exhibits unmonitored failures, degrades unexpectedly, or lacks diagnostic depth, this loop invokes the agentic `self-improving-loop` methodology to author new diagnostic skills.

## 2. Invariants & Guardrails

- **Zero Overhead**: Newly authored tools must not require external APIs or daemons.
- **Audited Tooling**: Any capability generated by this loop must pass the standard 2-cycle validation before integration.
- **Rollback Guarantee**: Does not mutate production code, only authors diagnostic rules, agent skills, or temporary `.agents/` utilities.

## 3. Workflow Steps

1. Ingest deployment status and execute `sidekick health`.
2. Analyze any degradation (e.g. 500 errors on routes).
3. Identify if the current telemetry/tooling provides sufficient diagnostic context.
4. If a capability gap is detected, transition into the `self-improving-loop` to build the missing diagnostic capability.
5. Exit gracefully with a summary artifact in `archive/tracers/log/`.
