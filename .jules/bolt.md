## 2026-07-31 - Memoize Derived Lookup Maps in High-Density Grids
**Learning:** Re-creating derived lookup maps (like `new Map()`) directly within the render body of heavy, high-density data views like `HourlyLoadsGrid.tsx` results in unstable references. This forces dependent callback hooks (`getHourValue`, `getMachineTotal`, etc.) to get re-created on every render, triggering cascading re-renders of the heavy `<DataGrid>` component. In addition, using simple keys like `machine_id` rather than composite keys (like `machine_id:shift_type`) can cause overlapping data across different categories or shifts to overwrite each other in the lookup map.
**Action:** Always wrap derived lookup data structures in `useMemo` to stabilize their references. Ensure maps utilize a composite key of `id:type` to prevent data collision, and leverage these memoized maps to replace O(N) array scans (e.g., `.find()`) with O(1) lookups within interaction event handlers.
