## 2026-07-26 - [Hourly Loads Re-render Stabilization]
**Learning:** In the high-density grid `HourlyLoadsGrid.tsx`, mapping the hourly load data on every single render creates massive GC churn and re-creates Map reference types. This, in turn, breaks dependency array stability in callbacks (`getHourValue`, `getMachineTotal`, etc.), causing the heavy `source` memoized data to re-calculate, leading to cascading re-renders in RevoGrid. Additionally, the original map used the non-unique `machine_id` as the key, causing data overwrite bugs when day and night records existed for the same machine.
**Action:** Always memoize intermediate derived data structures using `useMemo` with minimal dependencies, and use composite keys (`machine_id:shift_type`) to guarantee lookup uniqueness and prevent data collision in multi-shift grid datasets.
