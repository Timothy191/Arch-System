## 2026-06-25 - SystemClock Visibility-Gated High-Frequency Interval Optimization

**Learning:** High-frequency UI updates (e.g., 1-second intervals for analog clock rendering) create continuous CPU and main-thread overhead even when their containing Popover or Modal is completely closed. By gating these intervals based on the open state (`isOpen`) of the popover/modal, we can eliminate ~90% of re-renders for globally mounted components, significantly reducing idle CPU usage on lower-end tablets and dashboard terminals. To avoid up to 10 seconds of visual staleness upon opening the UI from a slower background sync interval, we must immediately sync the state of the clock hands on transition to `isOpen: true`.

**Action:** Whenever implementing or refactoring high-frequency intervals (e.g. timers, clocks, active SCADA gauges) inside modals, popovers, or collapsible drawers, always track the container's open/expanded state (`isOpen`) and make the interval conditional on that state. Consolidate immediate state synchronization and `setInterval` logic into a single `useEffect` dependent on the visibility/open state to ensure clean resource management and crisp, up-to-date visual feedback on open.
